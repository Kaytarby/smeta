# Память проекта smeta / Оперплан

Обновлено: 2026-09-10. Ветка сессии `arena/01a08b7d-smeta`.

## Решение, согласованное с пользователем

- Довести текущее до рабочего прода, не писать React/облако.
- **Без интернета.** Коллеги (6–15 человек, тысячи строк) в одной базе.
- Хост: рабочий **ноутбук, бывает выключен**. Это принято как компромисс: пока выключен — никто не работает.
- Боль: таблица и ввод.
- Можно усложнить ради надёжности (SQLite, бэкапы, тесты).

Отвергнуто: общий JSON/SQLite на SMB. Несколько писателей портят файл.

Принято: **один Node на ноутбуке**, коллеги открывают `http://IP:3000` в браузере той же сети.

## Что сделано 2026-09-10

1. LAN: `app.listen(0.0.0.0)`, баннер с адресом, `start.cmd`, автозапуск Windows `scripts/install-autostart.ps1`.
2. SQLite `data/operplan.sqlite` через встроенный `node:sqlite` (Node 22, без native-модулей). Миграция из `store.json` один раз. Бэкапы `data/backups/` (старт, каждые 6 ч, понедельник, кнопка).
3. Таблица: настоящий `<table>`, sticky шапка и колонка контрагента, правки недель на месте без полной перерисовки, группы сворачиваются, поиск контрагента по имени/ИНН. Шрифты системные (офлайн).
4. PUT недель больше не требует ИНН, если контрагента не трогали (иначе старые строки с пустым ИНН нельзя было править).
5. Секрет сессии в `data/session.secret`, пароль админа не светится на логине.
6. Тесты: `npm test` (9 шт.).

Нужен Node.js **22+**.

## Ограничение, которое кодом не лечится

Ноутбук выключен / ушёл из Wi‑Fi → база недоступна. Честно написано в UI и README. Лучше позже всегда включённый мини‑ПК.
