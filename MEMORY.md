# Память проекта smeta / Оперплан

Обновлено: 2026-09-10. Ветка сессии `arena/01a08bce-smeta`.

## Решение, согласованное с пользователем

- Довести текущее до рабочего прода, не писать React/облако.
- **Без интернета.** Коллеги (6–15 человек, тысячи строк) в одной базе.
- Хост: рабочий **ноутбук, бывает выключен**. Это принято как компромисс: пока выключен — никто не работает.
- Боль: таблица и ввод.
- Можно усложнить ради надёжности (SQLite, бэкапы, тесты).

Отвергнуто: общий JSON/SQLite на SMB. Несколько писателей портят файл.

Принято: **один Node на ноутбуке**, коллеги открывают `http://IP:3000` в браузере той же сети.

## Что сделано 2026-09-10 (сессия 1, ветка 01a08b7d)

1. LAN: `app.listen(0.0.0.0)`, баннер с адресом, `start.cmd`, автозапуск Windows `scripts/install-autostart.ps1`.

3. Таблица: настоящий `<table>`, sticky шапка и колонка контрагента, правки недель на месте без полной перерисовки, группы сворачиваются, поиск контрагента по имени/ИНН. Шрифты системные (офлайн).
4. PUT недель больше не требует ИНН, если контрагента не трогали.
5. Секрет сессии в `data/session.secret`, пароль админа не светится на логине.
6. Тесты: `npm test` (9 шт.).

## Что сделано 2026-09-10 (сессия 3): починка входа в превью

Симптом: «не заходит» — экран входа, кнопка «Войти» не пускает дальше.

Причина (две штуки, обе воспроизведены тестом):

1. **Cookie блокировались браузером.** Превью открывается по HTTPS и внутри встроенного фрейма на другом сайте,
   то есть в контексте third‑party. Cookie сессии была `SameSite=Lax` без `Secure` — такие cookie браузер
   не отправляет во фрейме. Логин отвечал 200, а следующий же `/api/me` приходил без cookie и получал 401,
   и приложение возвращалось на экран входа.
2. **Гонка в клиенте.** Проверочный `/api/me` при загрузке страницы отвечает 401 уже после успешного входа,
   и обработчик 401 затирал только что полученный токен — дальше все запросы шли без авторизации.

Как исправлено:

- `app.set("trust proxy", true)`; `sessionCookieOptions(req)` из `lib/logic.js` отдаёт
  `SameSite=None; Secure` за HTTPS и `SameSite=Lax` в локальной сети (http), так что LAN‑поведение не изменилось;
- `/api/login` возвращает токен в теле ответа; `requireAuth()` принимает cookie **или** `Authorization: Bearer`
  (`extractSessionToken`); клиент хранит токен (localStorage → sessionStorage → память) и шлёт его заголовком;
- в `api()` 401 больше не затирает токен, если он поменялся, пока запрос летел, и не трогает сессию для `/api/login`;
- выгрузка Excel и шаблон качаются через `fetch` + blob (по токену), с откатом на прямую ссылку;
- добавлен короткий журнал запросов в консоль сервера: метод, путь, код, время и каким путём авторизован
  запрос (`cookie` / `bearer` / нет). По нему сразу видно, доходит ли браузер до сервера.

Тесты: `npm test` — 14 (добавлены проверки cookie и разбора токена). Новый `npm run test:ui`
(jsdom, требует `npm install --no-save jsdom`) прогоняет вход в двух режимах: обычные cookie и полностью
заблокированные cookie — второй сценарий и есть превью. В `npm test` он не входит, чтобы установка
зависимостей на ноутбуке не требовала интернета.

## Ограничение, которое кодом не лечится

Ноутбук выключен / ушёл из Wi‑Fi → база недоступна. Честно написано в UI и README. Лучше позже всегда включённый мини‑ПК.
